# 驭智 · AI 协同编程考核平台

面向 C11 项目实践的 AI 协同编程考核平台，提供学生项目工作区、教师工作台、过程轨迹和基于证据的过程评价。

## 本地启动

需要 Node.js 22.13 或更新版本（使用内置 SQLite；建议部署在受支持的 Node.js LTS 上）。首次准备依赖使用 `npm ci`，已安装依赖时直接运行：

```sh
npm start
```

访问 http://127.0.0.1:4173 。可通过 `PORT` 修改端口。默认仅监听本机，可通过 `HOST` 配置；提供 `public/`、Monaco 静态资源、三份原始题面和轨迹 API，不提供 experiments 或其他资料目录。

## 界面与交互

- 首页：账号登录与学生注册。学生注册后自动进入学习空间，教师登录后进入教学工作台；服务端强制检查角色。
- 教师端：按账号选择学生，分别查看该学生的项目记录、过程轨迹、对话、历史快照及 JSON 导出。支持姓名/用户名搜索和项目筛选；同名学生不合并；教师试用与历史演示单列，不计入学生统计。

- 项目列表：对应 `problem/project1.txt`、`project2.txt`、`project3.txt` 三个独立考核，支持搜索与进行中筛选。
- 左侧题目：中文概述、评分分项、原始题面。
- 中间项目：文件树、文件夹折叠、新建文件、多文件标签、Monaco 编辑器、C11 语法高亮、每文件撤销历史与光标位置、可折叠终端。
- 右侧 AI 聊天：可折叠、快捷问题、发送消息、当前文件提示。
- 状态：按账号、项目隔离 localStorage 保存，保留文件、聊天、活动时间、标签及折叠状态；支持 Ctrl/Cmd+S 手动保存。仅在页面可见时累计活动时间，非正式考试计时。
- 导出：以 JSON 导出项目所有文件、对话与过程轨迹。
- 移动端：题目与工作区上下排列，AI 侧栏以抽屉显示。

## 当前边界

这是先行搭建的 UI 原型。项目文件位于浏览器本地虚拟工作区，不直接读写服务器上的学生目录。已包含账号认证与权限隔离；已接入服务端 DeepSeek 请求和经审批的文件变更；配置密钥后才能调用。已接入隔离的 C 编译运行和 Python 绘图；已接入教师端过程性初评与复核；考试提交和正式成绩发布尚未接入。历史演示/未执行记录保留原标记，新运行返回实际输出和退出状态，不自动判定作业正确。

编辑器禁用实验性 EditContext，使用兼容的输入模式，保留 Monaco 的编辑功能。依赖固定在 lockfile；浏览器资源由本机提供，不需要外部 CDN。安装 LangGraph 与 SQLite 检查点依赖需要 npm 网络访问。

## 代码入口

- `server.mjs`：本地静态服务、原始题面及轨迹接口。
- `src/trace-store.mjs`：轨迹持久化、事件去重、记录列表与读取。
- `public/trace.js`：编辑增量、轨迹同步与项目快照恢复。
- `public/teacher.js`：教师端记录、时间线、对话和快照界面。
- `public/projects.js`：项目元数据、中文概要及起始文件。
- `public/app.js`：路由、项目状态、编辑器与界面交互。
- `public/style.css`：页面样式及响应式布局。

## 验证

`npm run check` 检查 JavaScript 语法；`npm test` 检查旧项目状态迁移及修改内容保留。

已移除独立规划文档，默认打开 `src/main.c`。旧浏览器状态会迁移：删除规划文件及标签，未修改的 C++ 模板替换为 C 模板；已有代码修改原样保留，不自动改写学生实现。如果同时存在 main.c 与 main.cpp，保留两份以避免覆盖。

现已记录编辑增量与代码版本，基础轨迹可在教师端查看。编辑的技术分段不是语义上的评分单元；过程性评价会综合关联原始证据。

已在内置浏览器实际验证：项目入口与项目隔离、文件切换与编辑、保存后刷新持久化、AI 栏折叠与展开、演示聊天发送、原始题面读取、文件重名提示、终端读取文件、390px 窄屏布局。浏览器检查时没有错误日志。以上为初版界面的验证；新 AI 运行时的验证与限制见下节。


## 基础过程轨迹

进入项目后自动开始记录。已有工作区先记录“导入已有状态”，保留当前文件与既有对话，明确说明旧操作历史及时间未知，不补造过去轨迹。

记录包括进入/离开项目、查看/新建文件、编辑、手动保存、学生消息、系统演示回复、运行尝试、终端操作和导出。每次编辑记录时间、字符位置、删除/插入文本及撤销/重做标记。停顿 1.5 秒、持续编辑满 10 秒，或文件切换/保存/发送/运行/离开时封存一段，保留段内逐次编辑及修改前后全文。分段仅方便读取；它不是自动评分的行为单位。

浏览器保留待同步记录，失败时显示待同步状态并自动重试；事件 UUID 用于服务端去重。服务端为事件分配顺序并记录接收时间，通过临时文件和重命名保存到 `data/traces/<record-id>.json`。教师端读取该目录的数据，关闭页面或重启服务不删除已经收到的轨迹。

新记录由服务端绑定登录账号，同一项目可新建多次独立作答，每次有独立文件、对话、审批和轨迹；旧作答可继续打开。旧匿名记录保留为历史演示，不能由新注册账号认领。已同步的作答可从服务端恢复继续编辑；尚未实现正式考核提交/锁卷或防篡改审计。手工编辑记录的是编辑器变化，不凭输入方式认定代码的真实作者或学生掌握程度。未连执行环境的运行明确记录为“未执行”，演示回复也不作为真实 AI 调用。

新增验证：`npm test` 覆盖编辑增量重放、历史快照恢复、服务重启后的持久化、重试去重、重复事件冲突、离线重试与同步并发、原有状态迁移。浏览器端在独立的 4180 测试环境中实际验证了学生编辑/保存/聊天/运行尝试 → 教师记录 → 修改前后对照 → 历史快照 → 刷新持久化，测试数据保存在临时目录，不混入默认记录。测试用服务可通过 `PORT`、`TRACE_DATA_DIR` 隔离。

## 注册、登录与教师初始化

公开注册只创建学生，姓名供教师识别，用户名不区分大小写。密码要求 12–128 个字符；教师与学生使用相同登录机制，登录成功后按服务端角色跳转。教师可使用学生视图体验项目，产生的记录会标明教师自己的账号。

在服务器项目目录运行：

```sh
npm run setup:teacher
```

命令打印一个仅管理员持有的初始化链接。打开后自行设置教师用户名和密码；有效期 24 小时，创建成功即失效，重复运行会撤销旧链接。教师已存在时不能再次初始化，公开注册没有教师角色选项，也不会把第一位注册者升级为教师。链接不要放在公共页面或发给学生。

认证数据保存在 `data/auth/accounts.sqlite`，密码使用带随机盐的 scrypt（N=32768、r=8、p=3）散列。服务端持有可撤销会话，浏览器仅使用 HttpOnly、SameSite=Lax Cookie；HTTPS 模式启用 Secure 和 __Host- Cookie。会话有效期 7 天，退出即撤销。修改请求要求正确 Origin 和 JSON 格式，登录后的写入还检查 CSRF token。注册/登录按来源与用户名限流，密码计算限制并发。相关依据：[OWASP 密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

教师列表、详情、导出接口要求教师权限。学生无法读取教师记录或向他人记录追加事件；账号 ID 与记录所有者由服务端校验。旧匿名浏览器工作区继续留在原存储键中，不自动迁入新账号；旧同步轨迹可由教师以“历史演示”查看。

目前没有邮箱验证、自助找回密码、学校统一身份认证。姓名是注册者自行填写，不能据此验证真实学籍。浏览器保留本机缓存，进入指定作答时从服务端恢复已同步的文件与对话。未同步内容仍仅在原浏览器中，不能跨设备恢复。

## 网页部署

### 两人临时公网测试

可以通过 Cloudflare Quick Tunnel 将完整平台提供为临时 HTTPS 链接，不需要 GitHub Pages，也不修改个人主页。电脑必须保持开机联网；隧道重建会更换地址，换地址后可登录并从作答列表恢复已同步内容；未同步的本机内容仍需从原地址导出，所以测试中尽量保持同一条隧道。

公网测试设置 `REGISTRATION_MODE=invite`。学生注册必须填写一次性邀请码，服务端在事务内消费邀请码，重复或并发使用不会多创建账号。教师登录不受影响。当前两个邀请码保存在权限受限的 `data/deployment/invitations.json`；不要上传到公开仓库。账号额度仍为每人累计 30 元。

当前连接信息保存在 `data/deployment/public-url.json`。当前应用运行于 `yuzhi-public-app-scope.scope`，隧道运行于 `yuzhi-public-tunnel.service`；停止分享可执行 `systemctl --user stop yuzhi-public-tunnel`。这些临时服务不保证机器重启后自动恢复。公网服务必须使用生成的 HTTPS 地址作为 `APP_ORIGIN`，并与本地预览保持单实例。

本机普通 systemd 用户 service 启动的应用在执行 Bubblewrap 时出现 `loopback: Failed RTM_NEWADDR: Operation not permitted`；从已验证的当前会话启动并交由用户 scope 管理后恢复正常，没有关闭网络隔离或放宽执行限制。因此更换机器或启动上下文后，应对实际运行中的服务再次验证执行环境，不能只检查安装依赖。

当前版本适合**单个 Node 进程 + 持久化磁盘 + 同域 HTTPS 反向代理**。不能仅上传静态文件，也不适合直接使用不保留本地磁盘的无服务器运行环境。不要把 `data`、`.env`、实验目录或源代码目录映射为公开静态目录。

1. 安装依赖 `npm ci`；复制 `.env.example` 为 `.env`。
2. 设置 `NODE_ENV=production`、`APP_ORIGIN=https://你的域名`（不带末尾斜杠），将 auth、traces、agent、runs 四个数据目录配置到持久化磁盘。生产环境缺少 HTTPS 来源会拒绝启动。
3. 使用进程管理器运行 `npm start`。默认监听 `127.0.0.1:4173`，由同一域名的 HTTPS 代理转发页面和 `/api`。
4. 在目标服务器运行 `npm run setup:teacher`，完成教师账号初始化。若迁移本机已有账号，应同时迁移整个 auth、traces、agent 与 runs 数据目录。
5. 备份时停服务后复制 auth、traces、agent 与 runs 目录（SQLite 包含可能存在的 WAL 文件）；不要只在运行时复制单个数据库文件。账号与会话在重启后保留。

例如已有 HTTPS Nginx 站点的代理片段：

```nginx
location / {
    proxy_pass http://127.0.0.1:4173;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 5m;
}
```

仅在这个本机可信代理覆盖 `X-Real-IP` 时配置 `TRUST_PROXY=loopback`，让限流按客户端地址工作。如果使用容器或其他托管平台，需按其网络与持久化卷配置调整；当前轨迹文件写入按单进程设计，不要横向扩容多个实例。

验证：`npm run check`；`npm test`（HTTP 测试会监听临时本地端口）。测试覆盖公开注册不能提权、密码散列/错误密码、一次性初始化及并发消费、Cookie 会话重启持久化/过期/撤销、跨站请求/CSRF 拦截、学生禁止访问教师接口、跨账号轨迹覆盖与伪造归属拦截。浏览器使用独立临时数据验证学生登录、编辑同步、退出、教师登录及按学生姓名回看轨迹。


## 当前 AI 提示词与工具能力

网页 AI 使用百炼兼容接口的 `deepseek-v4-flash-0731`。教师在工作台的「AI 连接」输入密钥，或部署时设置 `AI_API_KEY`（优先于网页配置）。密钥仅由服务端保存和调用，接口不回传；学生无权修改。当前开发环境已由教师提供密钥，完成百炼 DeepSeek V4 Flash 的真实连接及“读取文件 → 提交局部修改提案”测试。部署到新服务器仍需迁移受限配置或重新设置密钥。

`prompt/AGENTS.md` 保留“学生规划、AI 按规划实现”，增加每次文件变更必须经过平台审批。每次模型调用按当前项目注入 `point/project1_考点.txt`、`project2_考点.txt` 或 `project3_考点.txt`，不把考点加入公开静态资源、学生接口或轨迹。禁止透露考点由系统提示词约束，仍需真实模型的对抗验证，不能承诺模型绝不泄漏。旧实验执行器继续加载历史 tutor-v1/v2，不据网页的新配置改写旧实验结论。

AI 工具包括列出/读取当前学生项目文件、检索原始对话、提出新建/修改文件，以及在隔离副本中运行已有代码并读取结果。变更提案可引用多条学生规划消息编号，原文由服务端提取；已有文件先读取，由服务端绑定版本，模型无需抄写哈希。支持 `edits` 局部替换，连续两次工具失败停止自动重试。提案显示路径和前后全文；学生选择「同意并应用」后才写入虚拟工作区。聊天中的“同意”不是审批。拒绝不会修改文件，等待期间文件内容变化会使应用失败，需重新读取并审批。工具引导每次最多 4 个文件，兼容旧提案上限 8 个文件；每个改动参数最多 16 KB、结果文件最多 100 KB、合计 200 KB，不授予宿主文件系统或其他学生数据访问权；命令只能在下述沙箱内执行。

教师轨迹区分学生编辑增量、AI 读取、变更提案、学生审批、AI 应用、失败与上下文整理。审批由服务端校验账号、提案编号及基准内容；AI 应用事件仅由服务端生成，客户端不能伪造此类事件。学生手动输入仍逐次记录，不因 AI 工具而改成只保存最终版本。过程轨迹不是防作弊证明；模型过程性初评需教师复核。

## 长程任务与上下文

采用 LangGraph 的持久化运行图、官方 SQLite checkpointer 和 interrupt/Command 暂停恢复。每条项目轨迹对应独立线程；关闭页面后任务继续在服务端执行，审批可以刷新页面后继续，服务重启后的未完成任务可手动恢复。平台保持学生审批状态，不把授权交给模型摘要判断。每轮最多 8 次模型步骤，避免失控循环；学生可发消息继续。

工作上下文先移除失败提案正文和过早的长工具输出，再按 `AI_CONTEXT_BYTES`（默认 70000 UTF-8 字节，不是精确 token 数；同时为系统规则和工具定义预留空间）决定是否摘要。压缩目标是降到触发阈值的一半，最近一轮学生消息及其工具交换整体保留，避免刚压缩就再次触发；若最近一轮自身过大，仍可能触发请求大小保护。原始对话、工具结果和编辑轨迹不删除，模型可用 `read_history` 按消息编号/关键词及偏移取回原话，用 `read_file` 读取当前文件。规则和私有考点每次重新注入。摘要有损，不能保证无限上下文或完全无遗忘，关键规划应从原文核对。

`data/agent/agent.sqlite` 保存检查点、原始模型/工具历史、调用缓存、费用预留和网页配置的密钥；目录权限 700、主数据库 600。此目录含敏感配置，应与 `data/auth`、`data/traces` 一起保存在受限持久化卷并一致备份。在线备份应使用 SQLite 备份机制，或停服后备份；不能只复制正在写入的主数据库而漏掉 WAL。部署仍限单实例。

网页调用使用独立账本，默认每个账号独立累计额度 `AI_USER_BUDGET_RMB=30` 元（跨项目、跨作答共用，包含上下文压缩，新建作答不重置额度），不动旧实验的 80 元账本。按输入 20 / 输出 60 元每百万 token 的保守系数预留/估算，输入预留采用 UTF-8 字节上界，结果不明的请求保留预留且不自动重试。额度由已认证的轨迹所有者绑定，不接受客户端指定扣费账号；并发请求先预留，额度不足只停止该账号的模型请求，仍可编辑和查看轨迹。教师试用也使用教师自己的独立额度。旧的无账号连接测试保留在总账，不扣给新学生。该估算不是百炼账单；部署者需核对所选模型的实际价格并配置供应商额度。摘要也消耗网页预算。成功调用按请求缓存，避免检查点恢复重复付费。

本地测试使用隔离的替身模型，不调用百炼：覆盖审批后重启恢复、拒绝不写入、文件版本冲突、所有权、私有考点选择、历史压缩与原始记录保留。HTTP 测试覆盖学生不能读写教师模型配置、学生不能读他人 AI 状态或审批、私有资料路径不可访问。真实 DeepSeek 的短消息连接已验证；教学遵循、完整工具调用质量与长程任务仍需进一步验收。

作答列表支持跨设备恢复已同步的工作区。同一项目同时在多个页面编辑可能产生版本冲突；平台保留本地内容并停止覆盖，需导出后核对。当前 AI 不提供删除/重命名编辑器文件的工具；已有代码可通过运行工具执行，新的源码仍须先经学生审批。


## 工作区编译运行与绘图

- 「运行项目」：当前打开 `.py` 文件时运行该 Python 文件；其他文件运行 C 项目。存在 CMakeLists.txt 时构建并执行 `main`；否则用 GCC C11 编译项目中的 `.c` 文件并链接 libm。不同目标、编译参数和测试脚本可在终端输入命令。
- 「输入与设置」：设置标准输入和 10/30/60 秒时限。运行采用批处理输入，不是交互式 PTY；终端每次命令使用新的项目副本，不保留 shell 的 cd、环境变量或临时编译产物。
- 预装 GCC、CMake、Python3、NumPy 和 matplotlib；工作区识别 Python 语法。`plt.show()` 自动保存 PNG；也可以显式 `plt.savefig('artifacts/plot.png')`。图片可放大查看并下载，CSV/TXT/JSON/PDF 可下载。
- 所有产物放在 `artifacts/` 保留目录，不在其中创建编辑器源码。后续运行自动把同项目最近一次有产物的结果带入该目录，因此 C 程序生成 CSV 后，Python 可直接读取绘图。失败运行若已产生文件，也会保留并标注实际退出状态。运行不会覆盖编辑器源码；程序对源码副本的写入不回灌。
- 教师时间线显示命令、标准输入、运行者（学生/AI）、源码事件序号与摘要、标准输出/错误、退出码、时长及产物。可查看本次运行对应的源码和图片。原始源码快照另外保存在服务端运行记录，不会因继续编辑而改变。学生只能读取自己的运行和产物，教师可回看；客户端不能伪造服务端运行事件。
- AI 的 `run_project`、`read_run` 工具接入同一服务，执行已有代码无需源码审批；新实现仍须先提案和审批，不能通过 shell 绕过。原始结果进入轨迹，AI 上下文只接收有界输出，可分页读取文本产物。相同 AI 工具调用恢复时复用已记录的运行，不重复执行。

### 执行环境与部署

当前后端使用 Linux Bubblewrap 命名空间隔离和 systemd 用户级控制组；没有可用隔离环境时拒绝执行，不回退到宿主裸运行。本机已经实测可用。Docker 并非当前必需依赖。

目标服务器需具备：Linux、cgroup v2、可用的非特权用户命名空间、systemd 用户会话，以及 `bubblewrap gcc cmake make python3 python3-numpy python3-matplotlib`。以普通服务用户运行 Node；用户会话需在退出登录后保留，可由服务器管理员通过 `loginctl enable-linger 用户名` 设置。仓库 `deploy/yuzhi.service` 提供 systemd 用户服务示例（按实际项目位置修改）。不要以 root 运行网页服务，也不要给沙箱挂载 Docker socket、数据库、密钥或整个用户目录。

在实际部署用户下先运行 `npm run runner:check`，再运行 `npm run test:execution`。普通单元测试不会假设主机具有隔离权限；专用测试才真实启动沙箱。通过后用同域 HTTPS 访问网页；`RUN_DATA_DIR` 设置运行数据与产物的持久化路径，默认 `data/runs`。备份需与账号、轨迹、agent 数据一起进行。非 Linux 或缺少用户会话的托管平台不能直接使用本执行后端。

每次运行禁用网络，系统工具只读挂载；最多 60 秒、整体 512 MB 内存（禁用 swap）、32 个进程/线程、一个 CPU 配额、64 MB 工作区和 32 MB 临时空间，单文件写入上限 16 MB；输出超过 128 KB 会停止。最多同时运行两项，每账号只能运行一项。无法在沙箱联网下载数据或 pip 安装依赖，需要预先准备依赖/输入文件。

每次源码快照最多 200 文件、2 MB；单个导出产物最多 2 MB、总计 4 MB、最多20个。测试账号最多保留200次运行和64 MB产物，达到上限会提示教师归档；未做自动清理，避免静默删除考核证据。代码运行结果尚未实现实时流式输出和长驻交互终端；AI 聊天已支持下述流式回复。重启中断的运行标为中断，已完成的结果及产物可恢复。

隔离实现遵循 [Bubblewrap 的明确挂载和命名空间边界](https://github.com/containers/bubblewrap#sandboxing)，但它不等于虚拟机隔离或防作弊系统。程序输出仍是不可信内容；应在受控组员测试范围使用，保持宿主系统更新。记录退出码为0只表示进程正常退出，不证明算法正确。

验证覆盖 C 标准输入与 CMake/GCC 构建、CSV 跨运行传递、Python 真实绘图、拒绝宿主私有文件/网络访问、超时、输出上限、停止任务、账号/产物权限、源码快照和 AI 调用接入。浏览器用独立测试账号实际运行 C 计时程序、Python 绘图、刷新回看并在教师端查看记录；示例图只表示测试程序的实际计时，不是题目实现或学生能力评估。
## 过程性评价

方案与评分规则见 [过程性评价方案](docs/process-assessment.md)。教师进入一份作答的“过程性评价”页签，可以生成四维硬评价和自然语言软评价，点击证据回看原事件，并修订确认。初评与复核历史分开保存；原轨迹变化后显示过期，需重新评价。未观察到的能力显示“待核验”，不自动记零分。

复用“AI 连接”中配置的模型，费用记入发起评价的教师账号。未配置模型或模型失败时明确报错，不生成模拟成绩。长轨迹分段提取证据再综合评价，超过容量会停止而非静默截断。教师需用真实案例校准模型的教育评价质量。

评价保存到 `data/assessments/`，可用 `ASSESSMENT_DATA_DIR` 指定持久化目录，部署时应与 auth、traces、agent、runs 一起备份。网页接口仅教师可用：`GET/POST /api/teacher/records/:id/assessment`、`POST .../assessment/review`、`GET .../assessment/export`。POST 沿用登录、同源和 CSRF 保护。

也可从原始轨迹 JSON 路径生成单独的评价文件（复用网页模型配置与账本，输出文件须尚不存在）：

```bash
node --env-file-if-exists=.env scripts/assess-trace.mjs /path/to/trace.json /path/to/assessment.json TEACHER_ACCOUNT_ID
```

支持平台导出轨迹及首轮实验 `state.json`。命令行输出不自动关联教师端作答；教师端直接评价该作答，保存版本和复核记录。网页不开放任意服务器路径读取。


## AI 流式回复与文件差异

学生聊天采用百炼流式响应与同源、需登录的 SSE 通道，文字边生成边显示；工具参数完整拼接后才校验执行，文件仍需逐次审批。断线自动重连当前草稿，离开页面不会取消服务端任务。完整回复保存在原始轨迹；连接失败且已有部分文字时标记为未完成记录，不作为完整回复或文件授权。主机断电时，尚未落盘的草稿不保证保留。摘要和教师评价继续使用完整响应。

审批窗口和教师编辑轨迹提供红色删除、绿色新增、原/新行号及增删统计，可展开前后全文。差异渲染使用文本转义；超大差异采用有界计算，可能将整段标为替换，不保证最小差异。

流式协议参考：https://help.aliyun.com/en/model-studio/stream 。使用 include_usage 接收末尾用量，已收到用量时记录估算值；缺失用量或请求结果不明时保留原预留，不自动重复计费请求。平台估算不是供应商账单。

## 学生长期记忆

教师工作台已拆成“过程轨迹”“过程性评价”“长期记忆”三个独立入口。长期记忆页按学生跨作答汇总，可从已完成评价提取候选观察，逐条修订确认、停用并回看证据。只有确认后的有效条目用于下一次 AI 协作；来源评价修订后旧记忆暂停使用。新证据可在教师确认后替代旧观察，过程评分器不读取旧记忆。

使用流程、更新规则和接口见 [学生长期记忆](docs/student-memory.md)。数据默认保存在 `data/memory/memory.sqlite`，部署时可设置 `MEMORY_DATA_DIR`，须纳入持久化和备份。没有新增依赖；后台服务重启后生效。


## 仓库内容与数据隔离

本仓库只包含产品源码、测试、题面、提示词、部署示例和技术文档。账号、会话、学生代码与对话、评价记录、运行产物、实验/训练数据、道路数据、API 密钥和临时访问地址均不随代码发布。`.env.example` 仅含占位配置；真实密钥应在服务端配置或通过教师端设置，切勿填写到前端代码。

### Project 2 道路数据（单独下载）

```sh
python3 scripts/download-road-data.py
```

脚本从 DIMACS 官方站点下载 Full USA、New York City 的距离权重图、时间权重图和共用坐标，支持断点续传并校验 gzip 完整性，清单记录解压文件的 SHA-256。需要 Python 3、curl 和至少约 5 GB 可用磁盘空间。安装目录为 `data/datasets/project2/`，被 Git 忽略。

安装完成后，Project 2 的每次隔离运行会只读挂载该目录中的解压文件到 `/workspace/datasets`，文件树显示资源清单，AI 系统上下文也包含路径。例如 `datasets/USA-road-d.NY.gr`、`datasets/USA-road-d.USA.gr`。这些文件不放入学生源码或轨迹快照。程序的 512 MB 内存、单次 60 秒限制仍适用，Full USA 全量实验可能超过限制。
