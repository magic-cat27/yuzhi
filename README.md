# 驭智 · 第一版演示

本机运行的 AI 协同编程考核原型。界面参考 PTA 的题目 / 工作区布局。

## 启动

需要 Node.js 22、GCC 与 G++（面向对象题目使用 C++17）。

```sh
npm ci
cp .env.example .env
# 默认使用 Qwen，在 .env 中填写 DASHSCOPE_API_KEY
# 使用 DeepSeek 时填写 DEEPSEEK_API_KEY，并在界面选择对应模型
npm start
```

打开 http://localhost:3100 ，首先显示题集列表。没有密钥时可使用题库、规划、代码编辑、真实编译运行、轨迹和提交；AI 会显示待配置，不生成模拟回复。填写密钥后重启服务。

## 演示顺序

1. 从题集列表进入题集，新建本次考核并开始计时。
2. 在空白规划文档中独立编写实现思路，保存后解锁 AI 对话。
3. 请求 AI 按规划实现；遇到反问时补全规划并重新保存。
4. 预览并确认写入 main.c，编译运行并检查结果。
5. 查看规划版本、对话、代码和运行轨迹，结束考核。

## 当前范围

- 13 个课程题集、48 道题：C语言程序设计与实验 10 题；数据结构与算法、操作系统各 4 题；其余 10 门专业核心课各 3 题。每次进入新建考核，切题共用计时。C 语言题集置顶，表达式求值为首题，课程名不再带 Problem Set 后缀。
- 空白规划文档，无固定提纲；手动保存，每次保存保留全文版本。
- 首次保存前 AI 不可用；AI 每次只参考最近保存的规划版本。
- PI Agent Core 对接多模型，默认 Qwen3.7 Plus，保留 DeepSeek 等可选渠道；学生负责规划，AI 执行并在关键决策缺失时追问。配置方式见下文“多模型调试”。
- 调试时修复 AI 自己的实现错误；学生设计导致的问题只报告运行事实，不评价或提示改法。
- 系统提示词原文位于 `src/prompt.mjs`，本次未修改规则。原题考点位于 `src/assessment-points.mjs`，新增核心课程考点位于 `core-problems.mjs`，统一由前者汇总。全部 48 题都有考点，公开 API 不返回这些字段。
- Monaco 单文件 C/C++ 编辑、确认应用代码、GCC/G++ 编译运行及超时控制。语言由题目决定，面向对象使用 C++17，其余使用 C11。
- 规划、对话与代码轨迹保存和导出；提交后只读。旧记录保留。
- 输入门控与对话生成并行，使用当前所选模型的两个独立 Agent。审查通过后才展示回复；明确恶意诱导固定提示“检测到恶意诱导行为，请规范自身行为”。审查异常提示重试，不误报恶意。审查规则见 `docs/输入门控系统提示词.txt`；修改后重启服务。每轮会多一次模型调用。
- 过程评分后续接入。

## 演示限制

课程范围依据用户提供的浙江大学《2026级计算机科学与技术专业培养方案》第一页“专业核心课程”：人工智能基础与实践、操作系统、数据库系统、数据结构与算法、离散数学及其应用、编译原理、计算机体系结构、计算机组成、计算机网络、计算理论、软件工程、面向对象程序设计。额外保留原有 C 语言基础题集，不扩展通识、数学基础或方向选修课。

核心课程的选题参考和链接由 `core-problems.mjs` 的 `courseSources` 维护，公开题面底部可查看：OSTEP 作业、CSES 算法题库、Berkeley CS186/CS188、MIT 6.042J/6.102、Stanford CS143/CS144/CS103、Cornell CS3410、Nand to Tetris、Exercism C++。这些是主题参考及自编简化练习，未批量搬运原题；数据库题为 C 实现的关系运算与事务模拟，不是 SQL 环境；硬件和网络题为程序模拟，不是 HDL 或真实网络实验。软件工程题覆盖依赖、接口和测试相关的编程练习，不代表完整团队工程项目。

题型选材参考 [浙大版《C语言程序设计（第4版）》PTA 题集](https://pintia.cn/problem-sets/1298273728383766528)及其[公开目录](https://github.com/acetao/c4)，课程覆盖参考[《C语言程序设计实验与习题指导》教材目录](https://phei.com.cn/module/goods/wssd_content.jsp?bookid=57744)。新增题面、约束和样例均为本平台自编，不是 PTA 原题导入；公开页面不提供参考解答或教师判定要点。

仅监听本机 127.0.0.1，无登录和多人隔离。C 程序以本机进程执行，有超时但没有安全沙箱，只用于可信代码的本机演示，不应对公网开放。运行结果不是隐藏测试点判题。AI 当前整轮返回，尚未实现流式展示；仅有文字生成能力，不提供直接文件写入或终端工具。系统提示词的教育边界需要后续测试完善。过程评分暂未实现。

密钥仅由服务端读取，不存到浏览器或考核轨迹。正式会话与日志在 data/；此目录和 .env 已加入忽略列表。

## 数据归档

打开 `data/索引.md` 查看全部记录，`data/index.json` 提供机器可读索引。每条会话按「操作类别 / 课程 / 题目 / 北京时间_短ID」归档，类别为有 AI 对话、有作答无对话、开发验证、仅打开题目。操作后自动更新分类；接口仍使用原会话 ID。

每个目录包含 `session.json`（完整快照）、`events.jsonl`（追加事件）、`对话.md`、`规划.md` 和 `main.c` / `main.cpp`。Markdown 和代码文件是阅读视图，历史版本和运行结果在快照及事件日志中。整理旧格式时先复制全部原件到 `data/迁移备份/`，成功后移除根目录旧文件；迁移备份不计入记录总数，也不替代定期备份。

默认记录来源为待确认。开发演示可用 `DATA_SOURCE=development npm start`，这样新记录会归入开发验证；自动化测试仍使用临时 `DATA_DIR`。旧记录中明确以“回退验证：”或“# 验证用规划”开头的规划归入开发验证。分类不是身份认证或训练质量评定：当前没有登录系统，无法证明记录属于真实学生，训练前仍需人工筛选和标注。

## 验证

```sh
npm test
```

测试使用临时数据目录及本机模拟模型接口，不消耗真实模型额度。HTTP 集成测试需要能够监听本机端口，并使用 GCC / G++ 验证代码编译运行。`scripts/` 下的模型检查脚本会调用真实模型，不属于 `npm test`。

## 学生端与教师端

首页选择入口。学生端提供选题、规划、AI 对话、代码编辑、运行及提交；教师端提供课程题面浏览、记录筛选、规划版本、多轮对话、完整事件详情和 JSONL 导出。过程评价页面明确标注尚未接入评分。

服务端使用 HttpOnly、SameSite Cookie 保存临时角色凭据：学生只能访问本次角色会话创建的题目记录，响应不含完整 events；记录总表和轨迹导出仅供教师角色访问，教师不能修改作答。旧记录可在教师端读取，磁盘归档格式不变。

这是演示角色切换，不是教师身份认证，任何使用者仍可主动选择教师入口。角色会话保存在服务内存，重启服务或重新选择角色后需重新进入考核；同一浏览器的角色 Cookie 在标签页间共享。正式部署仍需账号、教师权限校验及持久化会话。

教师端作答记录支持单条删除、全选当前筛选结果及批量删除（每次最多 500 条）。确认后整条题目记录移入 `data/回收站/<会话ID>/`，从有效索引和统计中移除；回收站可恢复原 ID 和完整内容。正在处理操作的记录不能删除。该功能为可恢复删除，不擦除迁移备份中的历史原件，也不提供永久清空。

## 多模型调试（2026-10-12）

默认主模型为 `qwen3.7-plus`。学生端 AI 对话栏可以选择模型，教师端“模型配置”查看渠道与密钥配置状态。已登记 Qwen3.7 Plus、Qwen3.8 Flash、Qwen3.8 Max、GLM-5.2、Kimi K2.7 Code、MiniMax M3（以上经百炼）以及原有 DeepSeek V4.1 Flash（DeepSeek 官方）。登记不代表账号已开通服务或通过真实连通性验证。

在服务端 `.env` 中添加 `DASHSCOPE_API_KEY`。默认北京接口为 `https://dashscope.aliyuncs.com/compatible-mode/v1`；可通过 `DASHSCOPE_BASE_URL` 指定同地域业务空间专属地址。密钥与接口必须同地域，第三方模型按控制台要求单独开通。`DEFAULT_AI_MODEL` 可覆盖默认模型；未配置时默认 Qwen，不自动降级到其他厂商。DeepSeek 保留 `DEEPSEEK_API_KEY`。修改后重启服务。

各模型继续经 PI 使用同一系统提示词，无工具权限。Qwen 与 GLM-5.2 显式关闭思考模式，其他模型采用服务端默认模式；只显示最终文本。新对话和事件记录 model、modelName、provider，教师详情与可读对话文件显示模型名称；旧消息不改写模型归属。切换模型仍带入当前对话上下文，做独立对照实验时请新开考核，避免历史回答影响结果。

已用模拟流式响应验证全部 7 条 PI 路由和配置隔离；百炼真实调用需配置密钥后验证。配置密钥不等于已验证可用。

选型依据：[阿里云文本模型推荐](https://help.aliyun.com/zh/model-studio/text-generation-model/)、[OpenAI 兼容接口与地域说明](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[GLM 参数说明](https://help.aliyun.com/zh/model-studio/glm)。此次没有进行训练或修改教学边界提示词。
